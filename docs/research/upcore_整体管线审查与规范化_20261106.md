# B4DL 主线管线审查与规范化

审查日期：2026-11-06；审查起点：`upcore` 的 `158bfe8`。目标是明确原始论文、现有实现与项目后续方向的关系，并修复本轮确认的训练入口问题。仓库共有约 799 个已跟踪文件、本轮以数据、特征、原训练入口、upcore 区域模型与监督、恢复和评测为重点抽查，并结合相关测试和静态检查；**不是对全部文件逐行审计**。MaskPLS、Grounded4D、AnswerSeg 保持历史研究和可选扩展的定位。

## 原论文与项目改进方向

[B4DL 原论文](https://arxiv.org/html/2508.05269v2)的模型训练分为静态 **3D LiDAR 理解**和序列 **4D LiDAR 理解**两阶段；编码器、LiDAR-文本投影和 metatoken 共同接入语言模型。六任务包括存在性、二元问答、时间定位、描述、时序理解和综合推理。论文的数据描述使用图像与标注生成，不能把输入模型的 LiDAR 单模态与数据生成来源混为一谈。

当前项目的整体目标继续是：**从原始 B4DL 及已核验 B3 基线出发，改善模型使用 LiDAR 时空证据回答问题的可靠性，同时维持六任务能力，并使数据、训练、推理及评测可追溯、可复现**。区域级时空表征、可核验数值观测、标签一致的配对训练和原任务回放是候选扩展；按[训练设计](upcore_训练管线改进与论文基线设计_20261104.md)先比较结构，再比较监督和回放，以完整评测决定是否保留。结构化 SFT、GRPO 与区域结构是实验路线，不应表述为原论文已有机制或已证明有效的改进。

## 审查发现及处理

1. **区域数据仍存在训练前的关键边界，待解决。** [`regional_data.py`](../../mllm/b4dl_core/regional_data.py) 的 v1 以非零 BEV 判断网格，并限制点均值在名义格内；[`regional_assets.py`](../../mllm/b4dl_core/regional_assets.py) 的 v2 依据实际体素分配和保留网格记录均值及范围外点。现有兼容层可能把范围外点夹入边界，而历史监督按名义范围过滤。v2 不能直接送入当前 [`regional_model.py`](../../mllm/b4dl_core/regional_model.py) 的格内约束。应先在真实帧量化差异，再明确输入、坐标和监督的一致性，设计版本化加载及模型契约；不能通过静默裁剪或改旧标签冒充兼容。详见 [v2 规范](../upcore/区域特征数据规范_v2.md)。
2. **原训练入口 LoRA 偏置保存与加载错误，已修复。** [`train.py`](../../mllm/vtimellm/train/train.py) 原先对字典直接解包并错误使用循环中残留的 `bias_name`，`lora_only` 遇到偏置时可能在保存阶段报错或选错偏置。现在由 [`lora_state.py`](../../mllm/vtimellm/train/lora_state.py) 单次遍历收集关联偏置，兼容 PEFT 的 `base_layer.bias` 和直接 `bias` 命名，保留 `none`、`all` 行为。另用 PEFT 小模型复现包装层偏置保存后无法按仓库加载顺序恢复，[`builder.py`](../../mllm/vtimellm/model/builder.py) 现将已匹配的包装偏置名映射到原基座，并拒绝映射冲突。小模型通过实际保存和仓库加载对照，DeepSpeed/ZeRO-3 及真实 7B 仍待验收。默认配置为 `none`，此修复不代表历史默认训练曾受该问题影响。`builder.py` 纳入主线实现身份，现有旧检查点门控仍然有效，不能绕过校验直接恢复。
3. **原始阶段脚本参数存在误配风险，已补充说明，尚未重构。** [`run_stages.sh`](../../mllm/run_stages.sh) 把不识别的参数传给两个阶段；[`stage2.sh`](../../mllm/scripts/stage2.sh) 的投影路径固定指向默认第一阶段输出。通用 `--output_dir` 会影响两个阶段但不会同步投影路径，可能读到旧投影或造成输出目录混用；缺少 `nvcc` 时脚本还会尝试安装依赖。根 README 原命令缺少 `cd mllm`，已修正并在 [`mllm/README.md`](../../mllm/README.md) 提示。未来应以独立阶段参数、显式上游资产身份和不覆盖输出的预检重构；该次没有改变历史脚本执行语义。
4. **评测和数据边界必须持续区分。** 六任务历史路径标记 `oracle_assisted_metadata`，自由输入路径单独固定 whole-scene 协议；两者不能混报。原 B3/SFT 自由六任务比较曾出现存在性、二元问答退化，不能仅凭结构化输出有效或 loss 下降宣称模型能力改善。原任务回放的 [`replay_prompt`](../../mllm/b4dl_core/reasoning/mixed.py) 移除 `<meta>` 后的内容，实际训练和各推理协议的差异需要在实验报告中明确，不应直接称为论文原始输入分布。
5. **规范债务需要分批处理。** 对 `mllm/b4dl_core`、`mllm/vtimellm/train`、`mllm/evaluation` 和 `mllm/tests` 的 Ruff `F` 检查发现 30 项既有未使用导入、无占位符 f-string 和未使用变量；其中某些导入承担运行时依赖预检。对模型和训练历史进行大规模纯格式改写会改变实现身份，故本轮只清理修改过的训练入口，并单独确认主线的未定义名称检查。后续按模块清理并核对冻结实验身份。

## 实施顺序与验收

1. 保留原论文两阶段与历史 B3 可重建基线；建立带版本和哈希的运行清单，复查分割、实际可见范围及数据暴露。新、旧资产不得覆盖。
2. 对真实 SST 小样本做 v1/v2、越界分配、帧位姿、缓存精度和原全局特征一致性审计；确定监督与输入边界后实现独立版本接入，随后做 1/5 token 的保存恢复和推理检查。
3. 在真实 7B CUDA 上做有界短跑，记录参数、损失、梯度、显存、速度、随机状态和恢复一致性；GRPO 概率对齐和旧 SFT 检查点迁移仍是独立门槛。
4. 固定原 B3、训练预算和评测口径，按 S1–S4、监督及回放逐项消融；先单种子筛选，再对选定方案与匹配基线进行三种子复验。完整六任务、几何观测/推导、配对和输入干预共同决定结果；保留失败样本与场景统计。
5. 延续 [upcore 验收门槛](../upcore/README.md)：六任务各主要指标相对原 B3 下降不超过 0.02，几何答案准确率和完整链通过率相对现有 SFT 均不下降且至少一项提高 1 个百分点。资产、训练完成、同口径对照和独立模型产物都需要证据；小模型测试不能替代效果验收。

## 本轮验证与限制

- Python 3.10.22、PyTorch 2.8.0 CPU、Transformers 4.47.0、PEFT 0.13.2；`python -m b4dl_core.runtime` 通过，CUDA 不可用。使用的是仓库运行目录下的兼容 CPU 环境，未验证原始 `wqlc` CUDA 环境。
- LoRA 偏置选择及 PEFT 小模型保存、仓库加载等专项检查 4 项通过；最终核心、推理、区域和论文评测选择性套件运行 162 项，158 项通过、4 项跳过。
- 全量 `mllm/tests` 发现 179 项，171 项通过、5 项跳过、3 项错误；三项错误来自演示依赖缺失（Pillow 或 Plotly），没有安装额外依赖。此全量运行发生在新增 PEFT 专项测试和加载修复之前。
- Ruff 对主线 `F821/F822/F823` 未定义名称检查和本轮修改的训练文件 `F` 检查通过；全量 `F` 的既有 30 项问题如上。没有运行真实数据提取、DeepSpeed、CUDA、正式训练或完整模型效果评测。
