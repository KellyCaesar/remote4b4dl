## 自动执行顺序

1. 等待几何和六任务两个编排都成功结束。六任务必须包括 SFT/B3 推理、双方指标与最终比较；状态失败、控制进程消失或等待超时则停止。
2. 核对固定 SFT 权重、B3/准备配置、源码实现、数据和自由六任务协议的身份；核对预测完成回执、文件哈希、全部请求 ID/输入指纹、分母、模型角色和指标哈希。重新计算六任务比较并与上游结果核对，输出 `endpoint-summary.json` 和 `six-task-comparison.json`。
3. 在同一 SFT 终点上，顺序运行 **internal_dev 全部 13,602 题 × 5 条件 = 68,010 次推理**：`identity`、`zero`、`repeat_first`、`shuffle_features`、`cross_scene`。每轮 greedy、seed42、最多 512 新 token；每轮完成后评分，四种干预分别与 identity 配对比较。
4. 按任务汇总准确率、结构有效率、数值误差、整链通过率；同时保留完整分母、可用配对数及场景 bootstrap 区间。跨场景缺供体、生成失败和截断不从完整分母移除。生成 `dev-error-audit.json`，区分答案错误、格式/生成失败、答案正确但证据链不通过及整链正确。每类前 8 个 request ID 仅作可追溯例子，不能视为代表性样本。
5. 输出 `report.md` 与 `next-step.json`：六任务主要指标若出现下降，优先建议研究六任务原训练监督回放与几何监督混合；否则优先按开发集弱项补强几何观测/过程监督。这里的下降只是描述性方向，不是统计显著性或预注册验收门槛。三项语言任务以主 NLTK METEOR 作优先级参考，报告仍保留全部指标。

后续训练候选需要独立实现与开发集验证；GRPO 首先需要定位采样与重算路径的数值问题，再进行有界工程验收，之后比较 outcome/scalar/process。脚本不修改优化器、裁剪阈值、数据或冻结模型源码，不会将当前 test 错例直接转换成训练样本。

本次诊断使用 internal_dev；它可能曾被历史 B3 见过，不能视为全新盲测。仍保留 CAM_BACK_RIGHT 裁剪输入；置零保留自车位姿。时间乱序是输入干预，不是上游 TSCD 对比解码。论文依据独立维护在 [论文依据与实现映射](B4DL本体更新_论文依据与实现映射.md)。

## 脚本与运行身份

- 编排脚本：`mllm/scripts/queue_reasoning_followup.py`，只依赖 Python 标准库，通过子进程调用已冻结的远端模型 CLI。
- 固定计划：`mllm/configs/reasoning_followup_20261101.json`，绑定当前 SFT SHA、数据 ID、协议 ID、源码实现身份和绝对路径。
- 输出：`/root/autodl-tmp/upcore-reasoning-20261030-r1/followup-dev-20261101-r1`。
- 独立部署：`/root/autodl-tmp/upcore-reasoning-20261030-r1/automation-20261101-r1/mllm/`。模型运行仍调用原 `run_root/mllm`，避免改变检查点所绑定的实现身份。
- 等待评测最长 72 小时，后续执行最长 72 小时，每个子阶段最长 24 小时；这些是停止预算，不是预计耗时。按当前原始输入速度，完整开发集每轮约 6–7 小时；干预可能改变输出长度，五轮实际耗时由日志确定。
- 使用独立队列文件锁，子进程继承锁；模型 CLI 另行使用既有 GPU 锁和空闲检查。不会与未退出的前序任务同时争用 GPU。失败保存日志和状态，不自动重试或调整参数。

在远端运行预检（不加载模型权重到 GPU、不启动推理）：

```bash
R=/root/autodl-tmp/upcore-reasoning-20261030-r1
Q=$R/automation-20261101-r1/mllm
"$R/runtime/wqlc/bin/python" "$Q/scripts/queue_reasoning_followup.py" \
  --plan "$Q/configs/reasoning_followup_20261101.json" --check-only
```

正式启动使用相同命令去掉 `--check-only`，后台日志重定向到独立部署目录 `controller.log`。首次启动要求输出目录不存在。已有部署启动记录见本文末尾，重复启动会被拒绝。

通过 SSH 查看：

```powershell
ssh autodl3 'cat /root/autodl-tmp/upcore-reasoning-20261030-r1/followup-dev-20261101-r1/status.json'
```

进入 SSH 后查看当前已生成条数：

```bash
R=/root/autodl-tmp/upcore-reasoning-20261030-r1/followup-dev-20261101-r1
find "$R" -maxdepth 2 -name predictions.jsonl -exec wc -l {} \;
cat "$R/dev-progress-summary.json"
```

停止队列：在输出目录创建 `STOP` 文件。等待阶段至多 30 秒响应，运行子阶段约 5 秒响应；只终止本队列启动的子进程。当前六任务评测由另一个编排管理。

显式恢复：核对原因、处理 STOP 后使用同一计划与脚本加 `--resume`。脚本核验已完成阶段的输出哈希并跳过它们；未完成推理使用模型 CLI 的相同身份恢复。评分/比较若在写完产物但尚未写入阶段回执时中断，会拒绝覆盖已有文件，需人工核对后另建输出方案。不会为了自动恢复删除结果或重新运行失败训练。若控制进程意外死亡而推理仍运行，子进程持有队列锁，恢复会拒绝并发。
