# SST 区域特征资产 v2

初版日期：2026-11-05；2026-11-07 更新。该规范对应 [`b4dl_core.regional_assets`](../../mllm/b4dl_core/regional_assets.py) 的 `b4dl-regional-features-v2`。现已新增版本化训练/推理加载路径，使用 `observed_assignment` 坐标策略并核验资产身份；真实 GPU 训练和全量资产尚待验证。历史全局特征、`b4dl-regional-features-v1` 与其严格格内约束保留。

## 来源和坐标

沿用历史 `CAM_BACK_RIGHT` 图像中心方形裁剪、相机深度大于 0.5 m、强度除以 255 的输入，以及现有 SST 配置与编码器。相机轴到 SST 轴为 `(x_s, y_s, z_s) = (z_cam, -x_cam, -y_cam)`，其逆为 `(x_cam, y_cam, z_cam) = (-y_s, -z_s, x_s)`。全部变换使用列向量，`a_from_b` 表示从 b 到 a：

```text
ego_from_sst = inverse(global_from_lidar_ego)
               @ global_from_camera_ego
               @ camera_ego_from_camera
               @ camera_from_sst
```

`global_from_lidar_ego` 取 LiDAR 关键帧时刻的自车位姿，`global_from_camera_ego` 取相机关键帧时刻的自车位姿。相机标定将相机坐标映射到相机时刻自车坐标。相机与 LiDAR 不要求同时刻，但各自的 sample_data 时间戳必须与对应 ego_pose 时间戳一致。`lidar_ego_from_lidar` 单独存储以核对几何父集；它不能直接代替上面的变换。后续若需全球坐标，可计算 `global_from_lidar_ego @ ego_from_sst @ [x_s,y_s,z_s,1]`。

SST 配置的 BEV 输出为 `[128, 80, 80]`，`index = y_index * 80 + x_index`，格宽 0.5 m，名义范围为 `x∈[0,40)`、`y∈[-20,20)`、`z∈[-2,4)`。v2 在同一次前向中观察 `voxel_layer` 给每个输入点分配的坐标和 `middle_encoder` 丢弃之后保留的 `voxel_coors`，再从 BEV 对应位置取值。因此有效性来自实际坐标，即使某个有效格的 128 维值全为零也保留。源代码、配置、权重及身份必须与已有来源回执一致；对不受支持的配置、输入点/有效格不匹配、散射范围外有非零输出等情形直接报错。

现有兼容层的动态体素化将名义范围外的裁剪点的体素索引夹到边界，点的原始坐标没有随之截断。v2 的 `xyz` 是**编码器实际分配到该有效格的全部原始 SST 点坐标的均值**，包括被夹到该格的范围外点。因此边界格均值可能位于名义网格以外，不能用格内坐标约束将它强行裁剪。每格与每帧分别记录范围外点数。范围外点分配、有效格和这一现象在真实数据上的比例仍需实际运行核验。

历史几何监督的支持记录按相机裁剪和名义体素范围计算；它与上述兼容层边界分配的语义并不完全一致。此处保留旧监督及哈希，不改标签或已有结论；后续必须在真实数据上量化差异，并审查输入支持与监督的一致性。v1 的 `sparse_cells()` 以非零输出识别网格，只平均名义范围内的点，不能当作 v2 的同义格式。

## 文件格式

一个新目录包含 `manifest.json` 与每场景一个 `scenes/<scene_id>.npz`，提取前要求输出目录不存在。使用 `--max-scenes` 可创建独立的小规模资产；此时 `complete=false`。每个场景的数组为：

| 字段 | 形状与 dtype | 含义 |
| --- | --- | --- |
| `global_features` | `[T,768]` float32 | 几何父集中的历史全局特征；逐帧重算与其比较通过后保存 |
| `offsets` | `[T+1]` int64 | 稀疏行的帧边界；第 t 帧为 `[offsets[t], offsets[t+1])` |
| `indices` | `[K]` int16 | 各帧升序、唯一的 `y*80+x` 有效格索引 |
| `values` | `[K,128]` float16 | 相应 BEV 特征，记录 FP16 量化误差 |
| `xyz` | `[K,3]` float32 | 实际分配到各格的全部输入点的 SST 轴坐标均值，单位米 |
| `point_counts`、`out_of_range_counts` | 各 `[K]` int32 | 每格分配点数及其中位于名义三维范围外的点数 |
| `global_from_lidar_ego`、`global_from_camera_ego` | 各 `[T,4,4]` float64 | LiDAR 与相机各自时刻的自车到全局变换 |
| `lidar_ego_from_lidar`、`camera_ego_from_camera` | 各 `[T,4,4]` float64 | 对应传感器标定变换 |
| `ego_from_sst` | `[T,4,4]` float64 | 上述坐标链计算的 SST 到 LiDAR 时刻自车变换 |

`K` 为该场景所有帧有效格数之和。稀疏格式的每一行均有效，不单独存储冗余掩码；消费者若需 `[T,N]` 布尔掩码，必须由 `offsets` 补齐生成，不能从特征是否为零推断。当前每帧必须至少有一个保留格。目标框、实例身份、参考答案不放入区域资产。

清单记录 schema 与内容摘要 `dataset_id`、父几何集和清单 SHA256、支持记录 SHA256、编码器回执与 checkpoint 身份、体素化/中间层/BEV 散射源码哈希、预处理设置、运行时版本与设备、每场景文件 SHA256。每帧记录 sample token、LiDAR/相机 sample_data、ego_pose 和 calibrated_sensor token、两传感器时间戳、原始 LiDAR 哈希、图像尺寸、点和格计数、历史全局特征重算误差及 FP16 特征量化误差。`load_scene(root, scene_id)` 验证清单摘要、场景文件哈希、数组形状与类型、索引和计数、刚体变换以及 `ego_from_sst` 链后返回 `(arrays, frames, manifest)`。

v2 的加载器校验原始资产、帧 token、LiDAR 时间、自车/传感器变换与父集全局特征；模型显式选择 `centroid_policy=observed_assignment`，按实际原始均值进行位置编码，不裁剪或伪造格内坐标。v1 使用 `strict_cell`，训练和检查点加载时要求策略与资产版本匹配。两种策略使用不同实验身份。旧监督按名义范围筛选，不能因模型现在接受真实均值便认为输入—标签一致；仍须量化并披露此差异。部分资产只允许显式指定工程子集的有界短跑，不满足正式训练完整资产条件。

## 独立提取

在具备已核验 SST 源码与权重、nuScenes 原始数据、几何父集及支持回执的 CUDA 环境中，先运行小规模工程检查：

```bash
export PYTHONPATH="$PWD/mllm"
python -m b4dl_core.runtime --require-cuda
python -m b4dl_core.regional_assets --geometry-dataset "$GEO" --tables "$TABLES" \
  --data-root "$RAW" --encoder-root "$SST" --support "$SUPPORT" \
  --output "$RUN/regional-v2-smoke" --device cuda:0 --gpu-lock "$LOCK" --max-scenes 1
```

该命令要求新的输出目录；GPU 锁与已有作业协调。完成后应检查清单中的全局重算误差、有效格和越界点统计、FP16 误差以及帧身份，再用原始点、传感器标定和相机/LiDAR 不同时刻位姿抽样独立复算坐标。不要把少量场景的完成标记当成全量结果。全量提取前应估算存储、耗时与数据覆盖，提取后单独核验全量哈希和缓存精度。

## 本次验证边界

本地 `wqlc` CPU 检查中，v2 共 8 项通过，覆盖相机轴、含平移与旋转且相机/LiDAR 时刻不同的坐标链及逆变换、实际兼容层的边界夹取、全零但有效的格、丢弃格、格内均值、来源哈希核验、哈希篡改和模拟提取读写；旧区域管线 5 项通过；核心回归 81 项中 79 项通过、2 项因缺少 nuScenes/pyquaternion 跳过。没有运行真实 nuScenes/SST 特征提取、相机与 LiDAR 真实帧对齐、CUDA、全量缓存精度或模型效果验收。
