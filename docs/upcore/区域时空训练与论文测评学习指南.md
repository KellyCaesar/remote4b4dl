更新日期：2026-11-05。本文面向希望理解和复现代码的读者，说明这次在 `upcore` 分支增加的数据、模型、训练和评测路径。研究设计及完整实验门槛见[训练管线改进与论文基线设计](../research/upcore_训练管线改进与论文基线设计_20261104.md)，已有 SFT 结果见[评测与论文对照](../research/upcore_SFT评测与LiDAR-Hallu论文对照_20261102.md)。

**当前状态：**候选训练管线和评测入口已在本地实现，通过了合成数据与微型模型的 CPU 检查；尚未完成真实 SST 区域特征重提、真实 7B CUDA 短跑、正式训练、完整六任务或论文同题模型评测。因此，当前不能宣称模型效果提升，也不能把小样例测试当作显存或性能验收。

## 1. 先建立整体认识

原始 B3 将每帧 SST 的全局特征投影到语言模型。此前的结构化 SFT 加入 A3 时序适配器，并让模型输出可解析的几何步骤，但六任务存在退化，数值证据链仍有缺口。新代码从同一个**历史三轮原始 B3**起步，尝试同时改善视觉输入、监督方式与训练数据组织。

```text
历史输入点云 + SST 编码器
        ├─ 原有每帧 768 维全局特征 ─────────────────────────┐
        └─ 池化前 128 维稀疏网格 + 点均值 + 坐标变换 ──┐       │
                                                       ↓       ↓
                                           区域聚合与时空融合
                                                       ↓
                                    每帧 1 个或最多 5 个视觉 token
                                                       ↓
                                  原 B3 投影支路 + 语言模型 LoRA
                                                       ↓
                         结构化几何步骤 / 短答案 / 原任务回答
                               ↑              ↑
                         数值观测辅助头    配对约束与原任务回放
```

结构化步骤是模型生成、可以用规则与真值检查的文本：`observe → derive → answer`。它可用于分析输出是否与观测和推导规则一致，**不能仅凭文本证明模型内部实际采用了同样的推理过程**。

## 2. 数据：区域特征从哪里来

原候选训练入口使用 [v1 区域特征提取与加载](../../mllm/b4dl_core/regional_data.py)和[批处理输入](../../mllm/b4dl_core/inputs.py)。本次新增独立的 [v2 区域资产及坐标规范](区域特征数据规范_v2.md)，用于按编码器实际分配生成网格和点均值；v2 尚未接入训练。

1. `extract()` 读取已有几何数据清单、原始 nuScenes 表、历史裁剪支持记录和锁定的 SST 编码器。它先检查源文件、编码器权重和预处理来源，再以已有点云裁剪路径重算编码器输出。
2. v1 的 `sparse_cells()` 根据非零 BEV 值选择网格，并只平均名义体素范围内的点。现有 SST 兼容层会将范围外点的体素索引夹到边界；因此 v1 点均值可能没有覆盖实际分配到边界格的全部点，也可能遗漏全零但有效的网格。v2 改为读取前向中实际分配的坐标和保留格，逐帧记录差异；详情见新规范。
3. `ego_from_sst()` 将 SST 的相机轴表达转换到 LiDAR 时刻的自车坐标，包含相机标定、相机时刻位姿和 LiDAR 时刻位姿。时空融合再结合每帧 `frame_geometry`，把不同帧的区域中心放到可比较的坐标系。
4. 区域值以 FP16 存储，索引、点均值和变换单独保存；清单记录来源、每场景哈希、全局特征重算误差和区域量化误差。`RegionalDataset` 加载时核验几何父集及区域资产身份。

读取一条样本后，关键张量为全局特征 `[T, 768]`、区域特征 `[T, N, 128]`、点均值 `[T, N, 3]`、索引和有效掩码 `[T, N]`、`ego_from_sst` `[T, 4, 4]`。`T` 是帧数，`N` 是该场景补齐后的有效网格上限；补齐项通过掩码排除。原始框、实例标注与参考答案用于监督和评测，不作为视觉输入。

输入仍受历史 `CAM_BACK_RIGHT` 裁剪约束。名义体素范围外的点在现有兼容层中可能被分配到边界，历史监督支持按名义范围过滤，二者差异需要真实数据审计。点均值不是点级分割真值；重算全局特征也不能代替真实硬件上的完整来源核验。

## 3. 模型：区域时空投影如何工作

主要代码：[区域模型](../../mllm/b4dl_core/regional_model.py)、[模型集成](../../mllm/b4dl_core/integration.py)、[视觉 token 展开](../../mllm/vtimellm/model/vtimellm_arch.py)。

- `LocalRegionPool` 将 `80×80` 网格划为 `8×8` 区域，每个区域覆盖 `10×10` 网格，约 `5×5` 米。它用网格特征和区域内位置计算注意力，再生成最多 64 个 768 维区域表示；空区域不参与有效注意力。
- `RegionalBlock` 在每帧内部让全局 token 与区域 token 交互。启用时间融合后，全局 token 贯穿全部帧；每个区域查找相邻帧的有效区域，默认选择 10 米内最近的最多 8 个，并可加入相对位置、朝向及时间偏置。无米制几何的对照使用区域网格距离选择邻居。
- `RegionalProjector` 保留原 B3 全局投影支路，另加 GELU 残差。新增残差的末层置零，使 **1 token 版本初始化时的有效帧输出与原投影一致**；训练后不再保证相同。5 token 版本另外输出最多四个空间分区 token，因此不是初始完全相同的语言输入。
- `visual_token_mask()` 根据实际有效区域计算每帧是一个全局 token，还是一个全局 token 加最多四个分区 token；上下文长度检查与视觉展开共用这个掩码。超过模型上下文时直接拒绝，而不是静默截断。

配置中的两层、8 头、768 维、10 米半径和 8 邻居是本项目的起始实验选择，不是论文证明最优的参数。新增表示是 BEV 区域表征，不代表实现了跨帧实例跟踪或点级分割。

## 4. 训练：三类监督分别解决什么问题

主要代码：[监督目标](../../mllm/b4dl_core/reasoning/supervision.py)、[混合采样](../../mllm/b4dl_core/reasoning/mixed.py)、[训练循环](../../mllm/b4dl_core/reasoning/trainer.py)。

### 4.1 结构化文本与数值观测

`segmented_trace_loss()` 分别计算观测、推导和答案段的平均 token 损失：

```text
L_trace = (L_observe + 0.5 × L_derive + L_answer) / 2.5
```

`ObservationHead` 从公开问题的冻结词嵌入、题目给出的帧索引和区域视觉表示读出数值，目标数字只进入损失，不输入查询。存在性监督计数；方位监督 `x、y`；距离监督各候选类距离；运动监督两端的 `d0、d1、y0、y1`。距离与坐标按 10 米缩放后使用 Smooth L1，计数使用 `log1p` 空间。模型输出仍可能错误，规则头、自由生成的观测值和最终答案要分别检查。

### 4.2 相反标签与选项轮换

`build_plan()` 只从训练场景构造两类有标签配对：

- **相反标签：**同一完整问题和帧数、不同场景，答案分别为 Yes 与 No。两条样本都学习正确短答案，T3 再用 margin 为 0.5 的 hinge 项约束正确答案相对错误答案的分数。
- **选项轮换：**同一个距离语义事件改变 A/B/C/D 对应关系；T3 把两次预测映射回语义类别后计算对称 JS 散度。答案字母变化本身不应改变所选物理类别。

当任务和谓词没有合法配对时，计划会选两条独立样本，并记录 `unpaired` 和原因，配对正则为零。计划以种子、输入数据、原任务来源哈希和逐步抽样记录构成 `plan_id`；不同对照复用同一个计划才能讨论增量贡献。

### 4.3 原任务回放与总损失

回放只纳入几何训练场景内的原训练对话。`replay_prompt()` 移除 `<video>` 等占位符和 `<meta>` 后的内容；原回答只作为监督目标。每次混合更新使用两条几何样本及两条回放样本。回放先均匀选场景，再在场景内选记录；由于缺少可靠的六任务标签，当前没有实现逐任务均衡。

T3 默认目标的代码计算为：

```text
L = 0.5 × (0.5 × L_trace + 0.5 × L_short + 0.2 × L_numeric)
    + 0.5 × L_replay + 0.1 × L_pair
```

其中 `L_short` 是同一公开问题下对候选短答案打分的交叉熵；两个几何样本分别计算后取平均。T0/T1 使用普通文本交叉熵，数值项和配对正则权重为零；T2 开启分段损失和数值项；T3 再开启配对正则。无回放对照将回放权重置零，保持同一个采样计划与几何项权重。实际日志记录各损失、短答案额外前向次数、耗时、梯度和 GPU 显存；**尚未自动汇总每组完整训练 token 数或 GPU 小时**，正式比较时需另行统计。

## 6. 操作示例：从准备到评测

以下是 Linux/云端 shell **示例，尚未在真实 7B CUDA 环境验证**。路径均为占位符；需要先确认环境、资产、可见范围、容量及 GPU 状态。输出目录必须是新的独立路径，实际训练和部署须按用户授权执行。

```bash
cd /path/to/mmb4dl
export PYTHONPATH="$PWD/mllm"
PY=/path/to/wqlc/bin/python
GEO=/path/to/verified/geometry-dataset
DATA=/path/to/verified/reasoning-v2
TABLES=/path/to/nuScenes/v1.0-trainval
RAW=/path/to/nuScenes
SST=/path/to/lidarclip
SUPPORT=/path/to/input-support.jsonl
ORIGINAL_QA=/path/to/original-train-qa.json
BASE=mllm/configs/core_geometry_baseline_original_b3_trainval.json
PREP=mllm/configs/core_geometry_preparation.json
RECIPE=mllm/configs/reasoning_grpo_v1.json
RUN=/path/to/new-independent-run
LOCK=/path/to/shared-gpu.lock

"$PY" -m b4dl_core.runtime --require-cuda

# 旧 v1 区域训练入口；其网格与边界点局限见本节和 v2 规范。
"$PY" -m b4dl_core.regional_data --geometry-dataset "$GEO" --tables "$TABLES" \
  --data-root "$RAW" --encoder-root "$SST" --support "$SUPPORT" \
  --output "$RUN/regional" --device cuda:0 --gpu-lock "$LOCK"

# 冻结 T 组公共计划；默认更新数是训练几何题数除以 4 向上取整。
"$PY" -m b4dl_core.reasoning build-mixed-plan --dataset "$DATA" --geometry-dataset "$GEO" \
  --replay-source "$ORIGINAL_QA" --seed 42 --output "$RUN/mixed-plan"

# S3 工程短跑。正式运行需删除 --engineering 和 --max-updates。
"$PY" -m b4dl_core.reasoning sft --dataset "$DATA" --geometry-dataset "$GEO" \
  --baseline "$BASE" --preparation "$PREP" --recipe "$RECIPE" --gpu-lock "$LOCK" \
  --regional-features "$RUN/regional" --regional-config mllm/configs/core_regional_s3_v1.json \
  --engineering --max-updates 50 --output "$RUN/s3-smoke"

# T3 工程短跑；若结构筛选选择 S4，应替换对应区域配置。
"$PY" -m b4dl_core.reasoning sft --dataset "$DATA" --geometry-dataset "$GEO" \
  --baseline "$BASE" --preparation "$PREP" --recipe "$RECIPE" --gpu-lock "$LOCK" \
  --regional-features "$RUN/regional" --regional-config mllm/configs/core_regional_s3_v1.json \
  --mixed-plan "$RUN/mixed-plan" --supervision-config mllm/configs/core_mixed_t3_v1.json \
  --engineering --max-updates 50 --output "$RUN/t3-smoke"
```

T0 使用相同 `--mixed-plan` 和 `core_mixed_t0_t1_v1.json`，但不传区域参数；T1 在 T0 的参数基础上加入选定的区域资产和区域配置；T2、T3 依次替换监督配置。正式区域训练要求完整区域资产及已核验的完整编码器特征。短跑完成回执只证明工程预算结束，不能证明效果达标。

几何评测示例：先对原始 B3 和新检查点分别生成并评分，再用显式的原始基线模式比较。若检查点来自 T 组，推理必须提供其同一混合计划；区域检查点还必须提供相同区域资产。

```bash
mkdir -p "$RUN/reports"
CKPT=/path/to/matched/final-checkpoint.pt
"$PY" -m b4dl_core.reasoning infer --dataset "$DATA" --geometry-dataset "$GEO" \
  --baseline "$BASE" --preparation "$PREP" --gpu-lock "$LOCK" --original-b3 \
  --split internal_dev --condition identity --output "$RUN/b3-dev"
"$PY" -m b4dl_core.reasoning infer --dataset "$DATA" --geometry-dataset "$GEO" \
  --baseline "$BASE" --preparation "$PREP" --gpu-lock "$LOCK" --checkpoint "$CKPT" \
  --regional-features "$RUN/regional" --mixed-plan "$RUN/mixed-plan" \
  --split internal_dev --condition identity --output "$RUN/t3-dev"
"$PY" -m b4dl_core.reasoning evaluate --dataset "$DATA" --geometry-dataset "$GEO" \
  --split internal_dev --predictions "$RUN/b3-dev/predictions.jsonl" --output "$RUN/reports/b3.json"
"$PY" -m b4dl_core.reasoning evaluate --dataset "$DATA" --geometry-dataset "$GEO" \
  --split internal_dev --predictions "$RUN/t3-dev/predictions.jsonl" --output "$RUN/reports/t3.json"
"$PY" -m b4dl_core.reasoning compare --original-b3 --base "$RUN/reports/b3.json" \
  --candidate "$RUN/reports/t3.json" --output "$RUN/reports/b3-vs-t3.json"
```

S 组检查点没有混合计划，推理时不传 `--mixed-plan`。T0 没有区域结构，不传 `--regional-features`。`--ablation` 用于相同训练资产和预算的 S/T 组间对照；`--intervention` 用于同一检查点的输入干预。六任务使用已有 `prepare-six-task`、`six-task-infer`、`six-task-metrics` 和 `six-task-compare`，区域或混合检查点的推理同样要携带相应资产。完整命令可参考[结构化推理说明](../../mllm/docs/upcore_reasoning_grpo.md)。

训练记录包含 `run.json`、`training.jsonl`、检查点、`latest.json` 和完成或失败回执；推理输出包含运行身份、逐题预测和完成回执。训练续跑要使用身份匹配的检查点及**新的输出目录**；推理的 `--resume` 用于恢复同一个输出目录，并核验已有结果。实现身份变化后，旧 SFT 检查点不满足新源码的严格身份检查；应保留旧源码评测旧模型，不能绕过检查或声称已完成迁移。

## 7. 如何与用户上传的论文比较

用户上传的《激光雷达语言模型真的理解时空关系吗？》译文位于 `D:/学习/mmb4dl-up/4DLLM Dis 仅译文.pdf`，原文件 SHA256 为 `79f34a4ca28b2d9e0876b7f263bf2d7af2250c1077f3d3ed4e339da63d197936`。论文对应 LiDAR-Hallu，预印本 `arXiv:2609.24452v1`；本项目固定其[公开仓库版本](https://github.com/Awesome4D/4DMLLM_Hallucination_Bench/tree/2ba623dabe2c59ea164e761320d537cdc09a6583)。

论文 150 个场景、五类任务各 2,000 题，共 10,000 题。论文报告 B4DL 总体准确率 **36.65%**，相反标签的 **348 对中 43 对同时正确**。这次使用固定版本的真实题目、五份 B4DL 默认归档预测和官方解析器复算，得到相同结果；测试中的 `sample_data` 映射是合成夹具。它核验了题目与归档评分流程，**没有核验本项目真实帧映射，更不是本项目模型在论文题集上的结果**。

已有项目 SFT 几何 test 准确率为 76.59%，但题目组成、可见范围、模型和输出协议与论文不同，不能用 `76.59% − 36.65%` 计算模型提升。两项既有结果的分任务细节和论文表 III–VII 见[已有对照报告](../research/upcore_SFT评测与LiDAR-Hallu论文对照_20261102.md)。

同题复测前，`paper_eval prepare` 检查固定题目哈希、150 个场景、论文归档中的序列长度，以及论文场景清单提供的参考样本索引；还要人工审计未由这些参考样本覆盖的帧、传感范围与特征预处理是否一致。代码把问题和答案分开，预测完成后使用固定的官方解析器。论文短答案解析按输出文本解析；达到 token 上限的截断状态会单列，仍可能被解析为有效答案，和几何结构化评测中截断直接记失败的规则不同。

```bash
PAPER=/path/to/pinned/paper-repository
"$PY" -m b4dl_core.paper_eval prepare --geometry-dataset "$GEO" --paper-root "$PAPER" \
  --sample-data "$TABLES/sample_data.json" --output "$RUN/paper-protocol"
"$PY" -m b4dl_core.paper_eval import-archive --geometry-dataset "$GEO" --paper-root "$PAPER" \
  --protocol "$RUN/paper-protocol" --output "$RUN/paper-archive"
"$PY" -m b4dl_core.paper_eval evaluate --geometry-dataset "$GEO" --paper-root "$PAPER" \
  --protocol "$RUN/paper-protocol" --predictions "$RUN/paper-archive/predictions.jsonl" \
  --output "$RUN/reports/paper-archive.json"

# 同题原 B3：论文默认温度 0.05，最多 32 个新 token。
"$PY" -m b4dl_core.paper_eval infer --dataset "$DATA" --geometry-dataset "$GEO" \
  --baseline "$BASE" --preparation "$PREP" --protocol "$RUN/paper-protocol" \
  --original-b3 --gpu-lock "$LOCK" --output "$RUN/paper-b3"
"$PY" -m b4dl_core.paper_eval evaluate --geometry-dataset "$GEO" --paper-root "$PAPER" \
  --protocol "$RUN/paper-protocol" --predictions "$RUN/paper-b3/predictions.jsonl" \
  --output "$RUN/reports/paper-b3.json"
"$PY" -m b4dl_core.paper_eval compare --literature --base "$RUN/reports/paper-archive.json" \
  --candidate "$RUN/reports/paper-b3.json" --output "$RUN/reports/paper-literature-vs-b3.json"
```

候选检查点的论文推理改用 `--checkpoint "$CKPT"`，区域及混合模型还需带上 `--regional-features`、`--mixed-plan`。`--alpha 1` 开启 TSCD：原始和乱序分支分别维护缓存，共享已生成的前缀，逐 token 使用 `z_clean + α(z_clean − z_shuffle)`；乱序成组改变帧特征及对应区域数据，时间和自车位姿条件保留。每题固定派生采样种子。论文原始归档的权重、缓存与采样种子并未随预测完整提供，文献对照结果须单列并说明输入和权重可能不同。

当前代码支持复算五份**B4DL 默认**归档预测、同题本项目模型、相反标签配对、运动正例召回/假正例率及 TSCD 推理。论文 B4DL-Ego、其他提示与 TSCD 强度的全部归档批量复算、候选内容先验、论文题集的选项轮换和视野支持子集审计仍需补充；不要把当前入口描述成已完成论文全部诊断。
